# ☕ 단체 음료 주문 (coffee-order)

**라이브:** https://wjoehasa-eng.github.io/coffee-order/ · 관리자: https://wjoehasa-eng.github.io/coffee-order/?admin=1

학교·팀 회의 때 **단체 음료 주문을 3단계로 오류 없이 취합하는 PWA**입니다.
이름을 고르고 → 메뉴를 고르고 → 한 번 확인하면 끝. 관리자 화면에서는 누가 무엇을 골랐는지,
무엇이 몇 잔인지, 누가 아직 안 골랐는지가 한 화면에 정리됩니다.

- **Firebase 실시간 DB** 연결: 한 번 읽고(캐시 즉시 표시) 이후엔 **새로고침 없이** 다른 사람 주문이 바로 보입니다
- 토스 스타일: `#F2F4F6` 바탕 · 흰 라운드 카드 · `#3182F6` 포인트
- 휴대폰(360~430px)에서 한 손으로, PC(1280px)에서는 가운데 카드로
- 설치형 PWA(오프라인 동작)

## 1. 누가 무엇을 보나

| 화면 | 주소 | 보이는 것 |
| --- | --- | --- |
| **참여자** (동료에게 보내는 링크) | `…/index.html#s=…` | 회차 배너 · 이름 선택 · 메뉴판 · 내 주문 확인. **명단 편집·브랜드·마감·통계는 없음** |
| **관리자** (선생님만 보관) | `…/index.html?admin=1#s=…` | 주문 현황·명단·메뉴판·회차 설정 |

관리자 화면의 **[회차·설정] → [🔗 참여자 링크 복사]** 는 누르면 **어느 회차의 링크인지 한 번 확인**한 뒤 복사합니다(다른 회차 링크를 잘못 뿌리는 사고 방지). 참여자 링크에는 `admin` 표시가 절대 들어가지 않습니다.

### 참여자 3단계
1. **내 이름** — 이름 검색 → 누르면 `○○○님 맞나요?` 확인(비밀번호 없음). 이미 주문한 사람은 `✓ 선택 완료 · 메뉴`로 표시되고, 다시 누르면 수정할 수 있습니다.
2. **메뉴** — 브랜드 메뉴판이 카테고리별로 뜹니다. 검색과 `HOT/ICE`만. (요청사항·직접 입력은 두지 않았습니다 — 확인 화면이 짧고 실수가 없습니다.)
3. **확정** — 요약 확인 → `주문 등록` → **바로** `○○○님 주문이 등록됐어요` (화면은 즉시 넘어가고 저장은 뒤에서 확인합니다)

### 관리자 4개 탭
- **주문 현황** — 정합성 배지 2개(`총원 N = 선택 A + 미선택 B`, `주문 잔 수 = 선택 인원`), 총원/선택/미선택 카드, 메뉴·옵션별 합계 표, `📋 주문서 복사`, 미선택자 목록, 선택 완료 목록(수정·취소).
  숫자가 어긋나면(명단 밖 이름의 주문, 같은 이름의 중복 주문) 배지가 **빨갛게** 바뀌고 `정리하기` 버튼이 나타납니다.
- **명단** — 한 명씩 추가, 여러 명 **줄바꿈·쉼표로 한꺼번에 붙여넣기**, 개별 삭제.
- **메뉴판** — 브랜드별 메뉴 **추가 · 이름/온도 수정 · 숨김(품절)**. 바꾼 내용은 참여자 메뉴판에 바로 반영.
- **회차·설정** — 브랜드 전환, 회차 이름, **주문 열림/마감**(열려 있으면 파란 `주문 마감하기`, 마감이면 회색 `다시 주문 받기`), **＋ 새 주문 열기(라운드 전환)**, 링크 복사, 연결 상태, **지난 회차 주문서·삭제**.

### 라운드 전환과 지난 회차
`＋ 새 주문 열기`를 누르면 지금 주문은 `history`에 보관되고 현재 주문판만 비워집니다. **명단은 그대로** 남아서 참여자 링크를 다시 보낼 필요가 없습니다.
`지난 회차` 목록의 `삭제`는 회차 이름과 건수를 보여 주고 한 번 더 확인한 뒤 지웁니다.

## 3. 저장 방식

| 모드 | 언제 | 어디에 |
| --- | --- | --- |
| **실시간 모드** (권장) | `#s=` / [회차·설정]에 `https://….firebasedatabase.app/ch/…` 를 넣으면 | Firebase 실시간 DB (여러 명이 동시에 주문해도 서로 덮어쓰지 않음) |
| **로컬 모드** | 연결하지 않았을 때 | 이 브라우저 `localStorage` (그 기기에서만) |
| **구글 시트 모드** (예전 링크 호환) | `https://script.google.com/macros/s/…/exec` | Apps Script 웹앱 + 구글 시트 |

### 실시간 모드가 빠른 이유
- **읽기**: `<base>.json` **한 번**으로 config·orders·menus·history를 모두 받아 `localStorage`에 저장합니다.
  두 번째 방문부터는 **저장분으로 즉시 그리고**(연결을 기다리지 않음) 뒤에서 최신으로 맞춥니다. 첫 방문에는 `명단 불러오는 중…` 스켈레톤이 보입니다.
- **쓰기**: 주문은 `orders/<회차>/<사람키>` 에 **사람별로 따로** 씁니다(`PUT`/`DELETE`). 키가 다르므로 동시에 주문해도 덮어쓰기가 없습니다.
  화면은 **누르는 즉시** 반영하고 저장은 뒤에서 확인합니다(버튼에는 잠깐 `저장 중…`).
- **실시간**: `EventSource`로 `<base>.json` 스트림을 붙여, 다른 사람의 주문·관리자의 마감/새 회차가 **새로고침 없이** 반영됩니다.

### 데이터 모양
```
<base>/config              회차ID·회차이름·브랜드·상태·명단·갱신시각
<base>/orders/<회차ID>/<사람키>   주문 한 건 (이름·메뉴·온도·시각)
<base>/menus/<브랜드>       메뉴 수정(숨김·이름·추가)
<base>/history/<회차ID>     지난 회차 주문 묶음
```

> `#s=` 주소는 **열쇠**입니다. 공개 저장소·SNS·열린 단체방에 올리지 마세요. 채널을 바꾸려면 새 `#s=` 링크로 한 번 열면 됩니다(연결 해제 버튼은 실수 방지를 위해 두지 않았습니다).
> 구글 시트로 돌아가야 하면 예전 `/exec` 링크를 `#s=`로 열면 그대로 동작합니다. 시트 설치·공유 방법은 [`apps-script/README.md`](apps-script/README.md).

## 5. 점검하기

```bash
python3 tools/test_app.py
```

- 참여자: 이름 검색·확인 팝업·메뉴 선택·즉시 등록·마감 차단 · **관리자 요소 0개**, 요청사항·직접 입력 없음
- 관리자: 명단 일괄 추가·브랜드 전환·메뉴 추가/수정/숨김·오입력 수정·취소·라운드 전환·**지난 회차 삭제**·마감 버튼 색·링크 확인 모달
- 실시간(Firebase 모의): 첫 방문 스켈레톤, 캐시 즉시 표시, 다른 화면의 변경이 실시간 반영, 주문 쓰기 1회, `저장 중…`
- 구글 시트(Code.gs) 계약: submit·roster·config·menus·newRound·**deleteHistory**·lite 응답
- 화면: **360px 가로 넘침 0**, 콘솔 에러 0, PWA 파일 200, 서비스워커 등록

## 6. 배포 (GitHub Pages)

지금 저장소는 **`gh-pages` 브랜치**를 게시 소스로 쓰고 있습니다(`https://wjoehasa-eng.github.io/coffee-order/`).

- 고칠 때: `git add -A && git commit -m "..." && git push origin main` 뒤에 **한 번 더** `git push origin main:gh-pages`
  (그래야 라이브에 반영됩니다. 웹앱을 고치면 `sw.js`의 캐시 이름과 `index.html`의 `?v=`도 함께 올려 주세요.)
- Settings → Pages → Branch를 `main` / `(root)` 로 바꾸면 미러 푸시 없이 `main`만 올려도 됩니다.
- 참여자에게는 위 라이브 주소를 그대로, 관리자는 주소 뒤에 `?admin=1`을 붙여 엽니다.
- 처음 한 번 관리자 화면에서 명단을 넣고 **참여자 링크**를 단체방에 보내면 됩니다.

> 앱 버전(`app.js` `APP_VERSION`)·서비스워커 캐시 이름은 화면을 고칠 때 함께 올려 주세요. 현재 `1.1.0` / `coffee-order-v1.1.0`.
