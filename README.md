# ☕ 단체 음료 주문 (coffee-order)

**라이브:** https://wjoehasa-eng.github.io/coffee-order/ · 관리자: https://wjoehasa-eng.github.io/coffee-order/?admin=1

학교·팀 회의 때 **단체 음료 주문을 3단계로 오류 없이 취합하는 PWA**입니다.
이름을 고르고 → 메뉴를 고르고 → 한 번 확인하면 끝. 관리자 화면에서는 누가 무엇을 골랐는지,
무엇이 몇 잔인지, 누가 아직 안 골랐는지가 한 화면에 정리됩니다.

- 토스 스타일: `#F2F4F6` 바탕 · 흰 라운드 카드(20px) · `#3182F6` 포인트
- 휴대폰(360~430px)에서 한 손으로, PC(1280px)에서는 가운데 카드로
- 설치형 PWA(오프라인 동작), 주문은 브라우저 저장 → 원하면 **구글 시트**에 모아 저장

---

## 1. 누가 무엇을 보나

| 화면 | 주소 | 보이는 것 |
| --- | --- | --- |
| **참여자** (동료에게 보내는 링크) | `…/index.html` (또는 `#s=…`) | 회차 배너 · 이름 선택 · 메뉴판 · 내 주문 확인. **명단 편집·브랜드·마감·통계는 없음** |
| **관리자** (선생님만 보관) | `…/index.html?admin=1` | 주문 현황·명단·메뉴판·회차 설정 |

관리자 화면의 **회차·설정 → 링크**에서 두 링크를 각각 복사할 수 있습니다.
참여자 링크에는 `admin` 표시가 절대 들어가지 않습니다.

### 참여자 3단계
1. **내 이름** — 이름 검색 → 누르면 `○○○님 맞나요?` 확인(비밀번호 없음). 이미 주문한 사람은 `✓ 선택 완료 · 메뉴`로 표시되고, 다시 누르면 수정할 수 있습니다.
2. **메뉴** — 브랜드 메뉴판이 카테고리별로 뜹니다. 검색, `HOT/ICE`, 요청사항(덜 달게·샷 추가·얼음 적게…), 맨 아래 **✏️ 직접 입력**까지.
3. **확정** — 요약 확인 → `주문 등록` → `○○○님 주문이 등록됐어요`

### 관리자 4개 탭
- **주문 현황** — 정합성 배지 2개(`총원 N = 선택 A + 미선택 B`, `주문 잔 수 = 선택 인원`), 총원/선택/미선택 카드, 메뉴·옵션별 합계 표, `📋 주문서 복사`, 미선택자 목록, 선택 완료 목록(수정·취소).
  숫자가 어긋나면(명단 밖 이름의 주문, 같은 이름의 중복 주문) 배지가 **빨갛게** 바뀌고 `정리하기` 버튼이 나타납니다.
- **명단** — 한 명씩 추가, 여러 명 **줄바꿈·쉼표로 한꺼번에 붙여넣기**, 개별 삭제.
- **메뉴판** — 브랜드별 메뉴 **추가 · 이름/온도 수정 · 숨김(품절)**. 바꾼 내용은 참여자 메뉴판과 시트 `Menus` 탭에 함께 반영.
- **회차·설정** — 브랜드 전환, 회차 이름, **주문 열림/마감**, **＋ 새 주문 열기(라운드 전환)**, 링크 복사, 시트 연결, 지난 회차 주문서.

### 라운드 전환 (1년 내내 같은 링크)
`＋ 새 주문 열기`를 누르면 지금 주문은 시트 `History`(로컬 모드에서는 브라우저 기록)에 보관되고
현재 주문판만 비워집니다. **명단은 그대로** 남아서 참여자 링크를 다시 보낼 필요가 없습니다.

## 2. 메뉴판 데이터 (`menus.js`)

2026년 11월 기준 각 브랜드 공식 메뉴·가격표 자료를 대조해 정리했습니다.
카테고리는 **커피 / 디카페인 / 음료·라떼 / 차 / 에이드·주스 / 스무디·프라페** 6개로 통일했습니다.

| 브랜드 | 메뉴 수 | HOT/ICE 모두 | ICE 전용 | HOT 전용 |
| --- | --- | --- | --- | --- |
| 컴포즈커피 | 52종 | 24 | 25 | 3 |
| 메가커피(MGC) | 57종 | 24 | 28 | 5 |
| 빽다방 | 53종 | 24 | 24 | 5 |
| 직접 설정 | 0종(편집자가 채움) | — | — | — |

- 매장·시기·프로모션에 따라 실제 메뉴와 다를 수 있어, **편집자 화면에서 언제든 고칠 수 있게** 했습니다.
- 신메뉴는 `메뉴판 → 메뉴 추가`, 이름이 바뀐 메뉴는 `이름·온도`, 품절은 `숨김`으로 처리하세요.

## 3. 저장 방식

| 모드 | 언제 | 어디에 |
| --- | --- | --- |
| **로컬 모드** | 시트를 연결하지 않았을 때 | 이 브라우저 `localStorage` (그 기기에서만) |
| **시트 모드** | 관리자 → 회차·설정 → 시트 연결에 `…/exec` 입력 | 구글 시트(여러 명이 동시에 주문해도 한 곳) |

- 참여자 링크에 `#s=<웹앱 주소>`가 붙으면, 링크를 받은 사람은 **버튼 없이 자동으로** 시트에 연결됩니다.
- 시트 설치·공유(사본 만들기) 방법은 [`apps-script/README.md`](apps-script/README.md).

## 4. 파일

```
index.html               화면 껍데기
styles.css               토스 스타일 디자인 시스템
app.js                   참여자/관리자 로직 (로컬·시트 두 저장 모드 공통)
menus.js                 컴포즈·메가커피·빽다방 메뉴판 데이터
manifest.webmanifest     PWA 설정
sw.js                    오프라인 캐시 (시트 요청은 캐시 안 함)
icon-192.png / icon-512.png / icons/   앱 아이콘 (maskable 포함)
apps-script/Code.gs      구글 시트 백엔드 (LockService·JSONP·doPost)
apps-script/README.md    시트 설치·사본 배포 안내
```

> 자체 점검 스크립트(`tools/test_app.py`)와 미리보기 이미지(`_preview*.png`, `_shot*.png`)는
> 제작용 산출물이라 저장소에는 올리지 않습니다(`.gitignore`).

## 6. 배포 (GitHub Pages)

지금 저장소는 **`gh-pages` 브랜치**를 게시 소스로 쓰고 있습니다(`https://wjoehasa-eng.github.io/coffee-order/`).

- 고칠 때: `git add -A && git commit -m "..." && git push origin main` 뒤에 **한 번 더** `git push origin main:gh-pages`
  (그래야 라이브에 반영됩니다. 웹앱을 고치면 `sw.js`의 캐시 이름도 함께 올려 주세요.)
- Settings → Pages → Branch를 `main` / `(root)` 로 바꾸면 미러 푸시 없이 `main`만 올려도 됩니다.
- 참여자에게는 위 라이브 주소를 그대로, 관리자는 주소 뒤에 `?admin=1`을 붙여 엽니다.
- 처음 한 번 관리자 화면에서 명단을 넣고, (원하면) 시트를 연결한 뒤 **참여자 링크**를 단체방에 보내면 됩니다.

> 앱 아이콘·서비스워커 캐시 이름(`coffee-order-v1.0.0`)은 화면을 고칠 때 함께 올려 주세요.
