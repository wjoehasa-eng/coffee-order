# 단체 음료 주문 — 구글 시트 백엔드 안내

앱만 써도 이 브라우저에 주문이 저장되지만, **시트에 연결하면 여러 명이 동시에 주문해도 한 곳에 모입니다.**
이 폴더의 `Code.gs`가 그 역할을 합니다.

---

## 1. 준비 (3분)

1. 구글 드라이브에서 **새 스프레드시트**를 만듭니다. 이름은 `단체 음료 주문` 정도면 충분합니다.
2. 그 시트에서 **[확장 프로그램] → [Apps Script]** 를 엽니다.
   → 이렇게 열면 스크립트가 그 시트에 **붙어(bound)** 있어서 시트 ID를 적지 않아도 됩니다.
3. `Code.gs` 내용 전체를 붙여넣고 **저장**(Ctrl+S)합니다.
4. 위쪽 함수 선택에서 **`setup`** 을 한 번 실행하고 권한을 허용합니다.
   → `Config` · `Orders` · `Menus` · `History` · `Backup` 탭이 자동으로 만들어집니다.
5. **[배포] → [새 배포] → 유형 `웹 앱`**
   - 설명: `단체 음료 주문`
   - 다음 사용자로 실행: **나**
   - 액세스 권한: **모든 사용자**
6. 나오는 웹 앱 주소(`…/exec`)를 복사해, 앱의 **관리자 화면 → 회차·설정 → 시트 연결**에 붙여넣고 `시트 연결`을 누릅니다.

> 배포 후 코드를 고치면 **[배포] → [배포 관리] → 수정 → 새 버전**으로 다시 배포해야 반영됩니다.

---

## 2. 다른 선생님께 나눠 줄 때 (사본 만들기)

이 앱은 **`SPREADSHEET_ID`를 비워 두면 언제나 "이 스크립트가 붙어 있는 시트"를 씁니다.**
그래서 배포용 양식으로 그대로 나눠 줄 수 있습니다.

1. 이 스프레드시트에서 **파일 → 사본 만들기**로 복제합니다.
2. 사본에서 **[확장 프로그램] → [Apps Script]** 를 열면 코드도 함께 복사되어 있습니다.
   (복사되지 않았다면 `Code.gs`를 다시 붙여넣으면 됩니다.)
3. 사본에서 **`setup` 실행 → 새 배포(웹 앱, 모든 사용자)** 만 하면 끝입니다.
4. 새로 나온 `…/exec` 주소를 받은 사람의 앱에 연결하면 **100% 똑같이 동작**합니다.

- 시트 ID를 고칠 필요가 없고, 서로의 데이터도 섞이지 않습니다.
- 각자 자기 사본·자기 배포 주소를 쓰므로 주문이 다른 학교로 새지 않습니다.

---

## 3. 시트 탭 구성

| 탭 | 무엇이 들어가나 |
| --- | --- |
| **Config** | `roundId`, `roundName`(예: `11/27 컴포즈커피`), `brand`, `status`(`open`/`closed`), `roster`(명단 JSON), `updatedAt` |
| **Orders** | `라운드ID · 이름 · 메뉴 · 온도 · 요청사항 · 시각` — 현재 라운드 주문만 |
| **Menus** | 브랜드별 메뉴 수정 내용(이름 변경·추가·숨김) JSON |
| **History** | 회차를 넘길 때마다 이전 라운드의 주문 전체가 한 줄로 보관됨 |
| **Backup** | 라운드 전환 시점의 주문 JSON 스냅샷 (최근 60개) |

---

## 4. 안전하게 만든 부분

- **동시 주문**: 모든 쓰기 요청이 `LockService.getScriptLock()` 안에서 처리됩니다. 30명이 같은 초에 눌러도 한 줄씩 차례로 기록됩니다.
- **중복 0**: 같은 라운드·같은 이름의 주문은 새 줄을 만들지 않고 **마지막 것만 남기고 갱신**합니다.
- **빈 값 덮어쓰기 차단**: 명단이 들어 있는데 빈 명단이 오면 `force` 없이는 거부합니다.
- **라운드 전환**: `newRound`는 현재 라운드 주문만 `History`로 옮기고 `Orders`에서 지웁니다. 명단은 그대로 남아 참여자 링크를 다시 보낼 필요가 없습니다.
- **개인정보 최소**: 이름·메뉴·요청사항·시각만 저장합니다. 전화번호·이메일·주소는 받지 않습니다.
- **단독 소유**: 스크립트는 자기가 붙은 시트 한 개만 읽고 씁니다. 공개 저장소에 시트 ID나 `…/exec` 주소를 올리지 마세요.

## 5. 앱이 부르는 동작

| action | 방식 | 하는 일 |
| --- | --- | --- |
| `ping` | GET | 살아 있는지, 시트가 열리는지 확인 |
| `load` | GET(JSONP) | Config·현재 주문·메뉴 수정·최근 회차 20개 |
| `submit` | POST | 주문 등록/수정 (마감이면 `closed` 반환) |
| `remove` | POST | 한 사람 주문 취소 |
| `removeMissing` | POST | 명단에 없는 이름의 주문 정리 |
| `config` | POST | 회차 이름·브랜드·열림/마감 변경 |
| `roster` | POST | 명단 교체(추가·삭제·일괄 붙여넣기 결과) |
| `menus` | POST | 브랜드 메뉴판 수정(이름·추가·숨김) |
| `newRound` | POST | 현재 주문을 History로 보관하고 새 회차 열기 |

`doGet`은 `callback` 파라미터가 있으면 JSONP로 감싸 돌려줍니다(`return handle_(p, p.callback);`).

---

## 6. 잘 안될 때

| 증상 | 확인할 것 |
| --- | --- |
| `불러오지 못했어요` | 배포 유형이 '웹 앱'인지, 액세스 권한이 '모든 사용자'인지, 주소가 `…/exec`로 끝나는지 |
| `시트에 Config 탭이 없습니다` | 편집기에서 `setup`을 한 번 실행 |
| 코드를 고쳤는데 그대로 | [배포 관리] → 새 버전으로 재배포 |
| 주문이 두 번 보임 | 앱의 관리자 화면 [명단 밖·중복 주문 정리] → 같은 이름은 마지막 주문만 남습니다 |
| `빈 명단으로 덮어쓰기를 차단했습니다` | 명단을 지우려면 일부러 `force`가 필요합니다(사고 방지 장치) |

---

## 7. 참고

- `SPREADSHEET_ID`는 기본이 빈 문자열입니다. **특정 시트 ID를 고정하고 싶을 때만** 채우세요.
- 스크립트 속성·외부 API를 쓰지 않으므로, 사본을 만들어 배포하면 그대로 독립적으로 동작합니다.
